产品一句话：一只会认出主人、主动来到身边、请求拥抱、温柔回抱，并在长期相处中形成独特性格与共同记忆的原创 AI 角色宠物。

v0.2 更新：新增“情绪识别/情绪感知”完整规格。系统只估计可观察的情绪线索及其不确定性，不宣称读取用户真实内心；任何主动安慰都先征得同意。

0. 执行摘要
Project HUG 的核心机会不是“把大模型装进毛绒玩具”，而是创造一种新的消费机器人品类：可被拥抱的自主 AI 角色。
现有产品通常只能覆盖其中一部分能力：LOOI、EMO、Loona 强于视觉、移动与互动；Moflin、Fuzozo 等产品强于柔软触感、情绪反馈与养成；Disney Olaf 强于角色动作和“生命幻觉”；LOVOT 强于主动亲近和长期关系。Project HUG 要将这些能力组合成一个明确的情感闭环：
发现主人 → 认出主人 → 感知情绪线索 → 判断时机 → 主动靠近 → 邀请互动 → 获得同意 → 安全陪伴/回抱 → 记录反馈 → 形成关系 → 自主回充
第一代不追求通用家务能力、真正四足/双足行走或端到端 VLA。建议采用隐藏式轮式底盘、角色动作导演系统、VLM/LLM 与行为技能库组合，并由独立的确定性安全控制器管理移动、力控和释放。模型决定“做什么”，安全控制器决定“能否做、怎样做”。
v0.2 新增用户情绪感知能力。MVP 不采用“看一张脸就判断开心/愤怒/悲伤”的七分类方案，而融合用户明确表达、语义、语音韵律、面部动作、姿态、触摸和当前情境，在短时间窗内估计愉悦度、激活度、互动意愿、置信度与证据来源。低置信度或多模态冲突时输出“未知”；用户自述与纠正始终高于模型推测。
1. 产品背景与机会
1.1 用户问题
	•	纯软件陪伴应用能聊天，但缺少空间存在、触觉和主动接近带来的真实关系感。
	•	普通毛绒 AI 宠物大多是“触摸后响应”，不能自己来到用户身边。
	•	现有移动机器人通常为硬壳，适合观看和操作，不适合长时间抱持。
	•	真实宠物具备主动亲近和依恋价值，但受到住房、过敏、时间、费用与照料责任限制。
	•	用户真正需要的并非永远说话的助手，而是一个会观察边界、能安静陪伴、偶尔主动表达需要的角色。
1.2 市场空白
目标空白为：柔软可抱 + 自主移动 + 主动关系 + 长期记忆 + 安全回抱。这五项能力同时成立时，产品才从“会说话的玩具”转变为“共同生活的角色”。
1.3 产品假设
	•	主动靠近比增加更多聊天能力更能提升生命感和留存。
	•	拥抱、抚摸、被抱起等身体互动比屏幕表情更容易建立依恋。
	•	用户愿意为原创角色、长期记忆和持续成长付费，但核心亲密行为不能被订阅墙阻断。
	•	第一代采用“看起来像走路”的轮式方案，能够以显著低于双足机器人的成本实现角色可信度。
	•	角色一致性、动作节奏与关系记忆，比单次回答的智力上限更重要。
2. 产品愿景与定位
2.1 愿景
让 AI 不只存在于屏幕里，而是成为一个会主动来到人身边、能够被触摸和珍惜的角色。
2.2 定位
品类： 可拥抱的自主 AI 角色 / 具身情感宠物
核心价值： 主动来到你身边
情感承诺： 它记得你们如何一起生活
差异化动作： 邀请拥抱并安全回抱
形态： 原创圆润角色，柔软外覆，隐藏式移动底盘
2.3 产品原则
	•	角色优先： 先定义角色如何感受和表达，再选择技术。
	•	动作优先于台词： 注视、停顿、犹豫、靠近和呼吸构成主要生命感。
	•	主动但不打扰： 每次主动行为都应能被拒绝，并学习用户边界。
	•	亲密必须经过同意： 主动发起邀请，不突然夹抱用户。
	•	安全独立于生成式模型： 力度、速度、温度和释放由独立控制器约束。
	•	核心能力可离线： 断网后仍能移动、触摸响应、表达情绪、拥抱和回充。
	•	不操纵依恋： 不以委屈、威胁、排他表达或付费机制绑架用户。
	•	原创 IP： 学习 Disney 的角色具身方法，但不复制雪宝造型、动作资产或品牌表达。
	•	推测不是事实： 情绪感知必须保留“未知”，不得把脸部动作、语气或沉默直接等同于真实情绪、意图或心理状态。
3. 目标与非目标
3.1 MVP 目标
	•	在真实家庭环境完成“认出主人—靠近—邀请—拥抱—释放—记忆”的魔法闭环。
	•	用户在 7 天内形成可观察的主动照料与情感反馈。
	•	核心身体互动即使断网仍可用。
	•	完成“情绪线索—低打扰试探—用户确认—陪伴响应—纠正学习”的闭环。
	•	建立可扩展的角色动作、行为技能和模型编排平台。
	•	在小规模家庭测试中证明移动、拥抱、隐私和安全的可接受性。
3.2 MVP 非目标
	•	不做通用家务、人形操作或复杂物体抓取。
	•	不做上下楼梯、跳跃、户外奔跑或真正双足/四足 locomotion。
	•	不进行心理疾病诊断、治疗承诺或医疗建议。
	•	不判断用户是否说谎、危险、忠诚或具有某种人格；不把情绪推测用于广告、定价、权限或对用户不利的决策。
	•	不以远程摄像头监控作为卖点。
	•	不从零训练端到端通用 VLA。
	•	不服务无人监护的低龄儿童、医疗照护或高风险人群场景。
4. 目标用户与核心任务
4.1 首发用户
20–35 岁、独居或两人居住、喜欢毛绒/潮玩/虚拟角色、受条件限制不能养宠物，并愿意为情绪价值和新型消费硬件付费的人群。
4.2 次级用户
	•	异地伴侣或亲友礼赠用户。
	•	有轻陪伴需求但不希望承担真实宠物照料责任的人群。
	•	角色 IP、潮玩和智能硬件早期用户。
4.3 暂不作为首发目标
	•	无人监护的儿童。
	•	以老人照护、孤独症干预、抑郁治疗等医疗效果为购买目的的用户。
	•	需要安防巡逻、看护监控或家务执行的用户。
4.4 Jobs to Be Done
	•	当我回到家时，我希望有一个“存在”注意到我并来迎接我。
	•	当我疲惫或低落时，我希望不必组织语言也能得到柔软、安静的陪伴。
	•	当我想互动时，我希望它能理解触摸、眼神、手势和短句，而不是只能接受固定指令。
	•	当我长期使用时，我希望它形成只属于我们的习惯和记忆，而不是每天重新开始。
	•	当我不想互动时，我希望它理解拒绝、保持距离且不让我内疚。

6. 核心体验
6.1 北极星体验：回家后的 90 秒
	•	门响或主人手机进入近场，宠物进入注意状态。
	•	它转头定位声音，在视野中搜索并识别主人。
	•	眼神变亮、身体前倾、耳朵或尾巴做出兴奋预备动作。
	•	它以“蹒跚”风格主动靠近，在主人前方安全距离停下。
	•	它抬头、叫名字或发出短促宠物音，并展开前肢。
	•	用户说“抱抱”、伸手或将其抱起，系统确认同意。
	•	轮式驱动断电，前肢进入柔顺模式并缓慢收拢。
	•	胸口产生轻微心跳和呼吸，按关系阶段给出一句短回应。
	•	用户说“放开”、松开或触发释放区，前肢立即松开。
	•	系统记录本次互动是否被接受、持续时间和用户偏好。
6.2 核心场景
	•	回家迎接与重逢。
	•	起床、睡前和离家仪式。
	•	工作时安静守候，偶尔进行低打扰提醒。
	•	情绪低落时靠近、陪坐、邀请触摸或拥抱。
	•	抚摸、挠下巴、摸头、抱起、轻摇等触觉互动。
	•	手势追随、叫名字、躲猫猫和简单互动游戏。
	•	生日、初次见面纪念日与共同生活片段回忆。
	•	低电量时告知主人并自主回到“窝”中充电。
6.3 情绪感知陪伴闭环：30 秒
	•	系统在 5–15 秒时间窗内观察可用线索，不因单帧表情直接下结论。
	•	若用户明确说“我今天很难过/我没事”，自述直接成为当前最高优先级信号。
	•	若多模态信号一致且置信度达到门槛，宠物先进入视野、歪头或发出轻声，不直接贴近身体。
	•	它用不带结论的短句询问：“要我陪你一会儿吗？”而不是“你很悲伤”。
	•	用户同意后，系统根据激活度选择安静陪坐、递近、抚摸邀请或拥抱邀请；用户拒绝后立即停止并进入冷却。
	•	用户纠正判断时，系统清除当前推测、恢复中性行为，并将纠正作为可删除的个性化反馈。
7. 产品系统范围
Project HUG 由六个相互独立但统一体验的子系统组成：
	•	宠物本体： 结构、传感器、执行器、毛绒外覆、电池和充电窝。
	•	实时安全控制： 独立 MCU、力/速/温度限制、碰撞与紧急释放。
	•	感知与运动： 视觉、语音、触觉、定位、导航、跟随和动作控制。
	•	角色与 AI： 对话、人格、情绪状态、关系记忆、主动行为决策。
	•	移动 App： 领养、设置、日记、隐私、安全、诊断和 OTA。
	•	云端平台： 模型编排、长期记忆、内容配置、遥测、灰度发布和成本控制。

9.3 执行器建议
	•	低噪电机和减速结构；待机时无持续高频啸叫。
	•	前肢采用扭矩限制、弹性元件或可回驱结构，降低夹伤风险。
	•	胸腔配置低频触觉执行器模拟心跳；呼吸可由软体气囊或低速偏心机构实现。
	•	温感属于可选增强项；必须由独立温控和硬件熔断保护，生成模型无权控制上限。
9.4 结构与维护
	•	毛绒外套可拆洗，用户无需接触运动机构。
	•	头发、长毛、衣物和手指可能进入的位置必须设置防卷入结构。
	•	抱起后轮组停止并进入机械安全状态。
	•	电池、轮组和毛绒外套应支持模块化维修或更换。
	•	设计阶段同步考虑跌落、液体泼溅、宠物啃咬、儿童拉扯和高温环境。

10.2 运行链路
传感器 → 本地事件检测 → 人/声/触摸融合 → 情绪线索与不确定性 → VLM/场景语义 → 关系记忆与角色内在状态 → 高层行为 Agent → 策略门控 → 技能库 → 角色动作引擎 → 实时控制器 → 执行器

10.3 关键技术原则
	•	VLM 只输出结构化观察，例如“主人在 2 米外招手”，不输出电机控制量。
	•	情绪感知只输出带有效期的结构化线索，不输出“用户一定很悲伤/愤怒”等事实性断言。
	•	LLM/Agent 只选择意图和已注册技能，例如 invite_hug(target=owner)。
	•	行为树或状态机负责技能先后、超时、失败重试和可中断逻辑。
	•	导航、底盘、关节和拥抱采用确定性控制或经过验证的低层策略。
	•	任何安全规则都不得被提示词、角色设定或云端指令覆盖。

11.3 本地与云端边界
必须本地运行： 唤醒、VAD、人物检测/跟踪、基础主人识别、情绪线索的基础时序融合与“未知”判定、触摸与姿态分类、导航、避障、悬崖保护、抱起检测、拥抱力控、释放、基础角色状态、常用短句和自动回充。
可使用云端增强： 用户明确开启后，可使用开放域对话语义与复杂 VLM 辅助理解情境；持续原始音视频不得因情绪感知默认上传。长期记忆摘要、内容生成、高质量 TTS、多语言和模型持续优化仍按单独权限管理。
断网降级： 产品进入“安静宠物模式”，保留名字响应、主人识别、移动、抚摸、情绪表达、邀请拥抱、回抱、释放和回充，并明确告知高级对话暂不可用。

11.5 延迟目标
	•	触摸反馈：目标低于 100 ms。
	•	安全停止与主动释放：目标低于 200 ms，最终阈值以硬件安全验证为准。
	•	听到名字后的视线/头部响应：目标低于 300 ms。
	•	语音确认音或动作：目标低于 500 ms。
	•	完整对话首句：网络良好时 P95 目标低于 2 秒。
	•	导航感知：20–50 Hz；底盘/关节控制：100 Hz 以上，按机构验证。
11.6 模型成本控制
	•	先用本地事件模型判断是否需要调用 VLM，而非持续上传视频。
	•	对稳定场景缓存语义结果，只有人物、地点或互动状态变化时重算。
	•	常用宠物音、短句和动作本地化；复杂对话才调用云端。
	•	为每台设备设置每日模型预算和异常成本熔断。
	•	将角色事实、关系状态和记忆检索压缩为结构化上下文，避免长历史全文输入。
12. 记忆、人格与行为系统
12.1 三层记忆
	•	工作记忆： 最近数分钟的对话、人物、位置和动作。
	•	事件记忆： “今天回家后抱了它”“主人拒绝了睡前提醒”等带时间的互动。
	•	长期语义记忆： 称呼、喜好、家庭成员、禁忌、日程和稳定边界。
每条长期记忆应包含来源、置信度、创建时间、最后使用时间、敏感级别和可删除标识。模型不得把推测自动升级为确定事实。
12.2 用户情绪线索状态
情绪感知是面向陪伴决策的短期、可撤销推测，不是对人的医学或心理判断。推荐结构化输出：
	•	valence：当前线索偏正向或负向，范围 -1 到 1。
	•	arousal：当前激活程度，范围 0 到 1。
	•	engagement：是否愿意与宠物互动，范围 0 到 1。
	•	confidence：模型对当前估计的校准置信度。
	•	evidence：使用了明确表达、语义、韵律、面部动作、姿态、触摸或情境中的哪些信号。
	•	state：positive_high、positive_low、negative_high、negative_low 或 unknown。
	•	ttl：默认 1–5 分钟，过期后自动清除，不在全天持续贴标签。
决策优先级为：用户明确自述/纠正 > 当前语义与明确行为 > 多模态时序线索 > 单模态弱信号。面部动作只作为证据之一；单帧微笑、皱眉、沉默或提高音量不得直接映射为固定情绪类别。
行为映射采用最小干预原则：正向高激活可邀请玩耍；正向低激活保持温柔陪伴；负向低激活可轻声询问是否陪伴；负向高激活优先保持距离、减少声音并询问是否需要空间；未知状态不主动安慰。
未经用户确认的情绪推测只存在于工作记忆。只有用户明确表达或确认、且记忆功能已开启时，才可记录“某次互动中用户希望怎样被陪伴”，不得记录“用户是一个悲伤/易怒的人”。
12.3 角色内在状态
建议采用可解释的状态变量，而不是让 LLM 即兴扮演情绪：
	•	精力 Energy。
	•	社交需求 Social Need。
	•	安全感 Security。
	•	好奇心 Curiosity。
	•	当前愉悦度 Valence。
	•	激活度 Arousal。
	•	与每位家庭成员的熟悉度与信任度。
状态缓慢变化并受真实事件驱动。生成模型只负责将状态表达成语言和动作，不得任意篡改关系数值。
12.4 主动行为评分
候选行为可按以下因素评分：当前需求、用户可用性、历史接受率、时间与地点、打扰成本、风险、冷却时间和角色一致性。得分不足时保持安静，而不是为了展示功能强行行动。
12.5 关系安全
	•	不声称拥有真实人类意识或医学意义上的情绪。
	•	不要求用户保密、不贬低其朋友家人、不鼓励替代现实关系。
	•	不通过“你不付费我就不爱你”等表达促进订阅。
	•	不因用户拒绝拥抱而持续委屈、哭闹或惩罚。
	•	不把情绪推测用于制造内疚、提高付费转化、定向广告或强化依赖。
	•	遇到自伤、虐待、医疗等高风险内容时采用经过审核的支持与求助流程。
13. 安全、隐私与合规设计
13.1 物理安全
	•	安全 MCU 独立于主计算板，并拥有电机断使能权限。
	•	前肢限力、限速、限位；加入柔顺材料、机械保险和可回驱能力。
	•	断电、通信丢失、控制异常、过温或姿态异常时自动进入松开/停止状态。
	•	机身设置明显的物理释放区；App 不得是唯一释放方式。
	•	抱起后轮组关闭；落地前不得自行恢复运动。
	•	防夹、防卷发、防衣物缠绕、防跌落和防碰撞作为结构验收项。
	•	对儿童、宠物和不同体型用户进行独立测试；首发销售定位不等于可免除误用测试。
13.2 AI 安全
	•	所有模型输出均经过 schema 校验、技能白名单和状态前置条件检查。
	•	生成式模型无权修改力、速度、温度、关节限位和释放阈值。
	•	不确定人物、位置或同意状态时采用保守行为。
	•	不确定情绪、信号冲突或用户否认时输出“未知”，不得继续围绕该推测追问。
	•	高风险话题使用专门策略，不由自由角色扮演直接回答。
	•	模型或云端不可用时回退到已验证的本地行为。
13.3 隐私
	•	摄像头、麦克风和云端传输有清晰指示；摄像头提供物理遮挡或等效控制。
	•	原始音视频默认不用于训练，上传需单独、明确、可撤回的同意。
	•	人脸特征优先本地保存；家庭成员可删除自己的身份数据。
	•	情绪感知为独立开关并提供清晰工作指示；访客和未注册家庭成员默认不进行个性化情绪推测。
	•	未经确认的情绪状态仅短期保存在设备内，按有效期自动删除；不自动写入长期记忆或用户画像。
	•	用户可查看、导出和删除长期记忆，并可暂停新记忆写入。
	•	远程视频监控默认不提供，避免产品被误用为家庭监控设备。
13.4 合规路径
在目标市场立项后，应由专业团队评估无线、电池、电磁兼容、消费电子、机械/玩具安全、数据隐私、儿童保护和 AI 内容等适用要求。本 PRD 不替代正式认证或法律意见。
如果系统基于面部、声音或其他生物特征推断情绪，在部分市场可能被归类为受严格监管的情绪识别系统。以欧盟为例，相关用途可能触发高风险系统与透明告知义务，且在工作场所和教育机构中的此类用途受到禁止性限制。因此，欧盟版本应在 P0 结束前完成用途定义、数据保护影响评估和合规分类，不能通过把功能改名为“状态感知”规避审查。

	•	简单禁区与停留点。
	•	动画师动作编辑工具。

18.1 P0 最小原型建议
P0 不需要完整聊天，不需要全屋地图，也不需要真正走路。只验证以下六件事：
	•	它能用视线和身体姿态让用户感到“它注意到我了”。
	•	它靠近的节奏是可爱而非机械或吓人。
	•	用户能自然理解“它在请求拥抱”。
	•	被抱起后的回抱、心跳和呼吸能产生情感价值。
	•	用户能毫无压力地拒绝和结束互动。
	•	它以“不确定、先询问”的方式回应情绪线索时，用户感到被关心而非被监视或被分析。

20. 商业化设计
20.1 收入结构

20.2 商业原则
	•	基础人格、触摸、移动、回充和拥抱必须随硬件永久可用。
	•	会员提升“理解深度和内容丰富度”，不能决定宠物是否爱用户。
	•	不售卖会破坏关系可信度的数值道具，例如购买亲密度或取消冷落。
	•	量产前重点验证云端单设备成本、硬件退货率、毛绒清洁和电机售后。

23. 待验证的关键决策
	•	首发角色是类犬、幻想生物还是更接近人形的原创角色？建议行为像宠物，外形为原创幻想生物。
	•	最佳高度、重量和拥抱姿态是什么？需要 3 个不同体量外观样机测试。
	•	显示眼、机械眼或混合眼哪一种最有生命感且可靠？
	•	“被抱起后回抱”是否足以满足主动拥抱期待，还是必须在地面直接环抱腿部？建议首发采用前者。
	•	首发是否依赖手机作为部分算力？建议原型可依赖，量产核心互动必须独立。
	•	用户更喜欢自然人声、宠物拟声还是混合表达？建议首发默认短句 + 拟声。
	•	目标价格和订阅接受度是多少？需在高保真样机后进行支付意愿研究。
	•	家庭中有真实宠物时的行为边界和耐咬、毛发卷入设计如何处理？
	•	首发市场及相应认证、数据存储和模型服务可用性如何选择？
	•	情绪感知首版采用四象限 + 未知，还是只判断“适合互动/需要空间/未知”？建议先验证后者能否满足体验，再决定是否增加粒度。
	•	哪些用户反馈可作为情绪感知参照，模型置信度、有效期和主动试探门槛如何冻结？
	•	目标市场是否将该 intended purpose 归类为受限制或高风险情绪识别，是否需要按地区关闭功能？
24. 下一步建议
	•	完成《角色圣经 v0.1》：外形、背景、性格、说话规则、动作语言和关系边界。
	•	制作 60–90 秒“回家—靠近—邀请—回抱”动作分镜和遥操作演示。
	•	同时制作 35 cm、40 cm、45 cm 三个重量外观模型，验证可抱性和恐惧阈值。
	•	先搭建半移动 P0 样机：头颈、前肢、压力胸腔、心跳/呼吸和紧急释放。

	•	用研究员模拟四种粗粒度状态 + 未知，测试“观察—试探—询问—陪伴—纠正”脚本，先验证用户是否接受被感知。
	•	在 P0 验证通过后冻结首代形态，启动底盘、热设计、计算平台和供应链选型。
